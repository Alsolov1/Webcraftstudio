WEBCRAFT ADMIN + CUSTOMER REQUESTS

1. The admin account must already exist in Supabase Authentication > Users.
2. Run admin/supabase-setup.sql only if you have not already created public.admin_users and inserted your admin user.
3. Run admin/customer-requests-setup.sql in Supabase SQL Editor. This creates the customer_requests table and RLS policies.
4. The customer_requests SQL has already been executed in your Supabase project; do not run it again.
5. Upload the CONTENTS of this folder to the ROOT of your GitHub Pages repository. Keep index.html, CNAME, og-image.jpg, and admin/ at the same level.
5. Visit https://webcraftdz.online/admin/ and sign in.
6. Submit a test request using the public contact form. It is stored directly in Supabase. Formspree is no longer used.

SECURITY NOTES
- The publishable key is intended for browser use. Never put a service_role or secret key in this repository.
- Visitors can INSERT new requests only. They cannot SELECT, UPDATE, or DELETE requests.
- Only authenticated users listed in public.admin_users can read/update/delete requests.
- This is a static frontend; all access control is enforced with Supabase Row Level Security.
